# Nest — implementation plan

This plan follows `ENGINE.md` (the spec). It records what is built in which
order, the decisions the spec leaves open, and every place where the build
environment forces a deviation. Results are appended to `REPORT.md` per
milestone (spec §15.1).

## Goal

Highest Elo on both primary machines (Ivy Bridge Intel Mac, Apple Silicon),
with no feature that only one of them can run. In practice that means:

- every hot path has an SSSE3/SSE4.1 kernel and a NEON kernel that are
  bit-identical to the scalar reference; AVX2/AVX-512 are extras;
- magic bitboards are the default; PEXT only on `bmi2` targets;
- strength decisions go through SPRT, speed decisions through the
  bench-signature rule (spec §10.4).

## Milestone order

Spec §14, unchanged: M0 build + bitboards, M1 position + legal movegen
(perft), M2 UCI + plain alpha-beta + PSQT eval, M3 HalfKP NNUE, M4 PVS / TT /
move picker, M5 pruning list one SPRT each, M6 Lazy SMP, M7 XBoard, M8 pinned
modern Stockfish net, M9 framework, M10 extras.

## Decisions

| Topic | Decision | Why |
|---|---|---|
| Phase-1 net | `nn-62ef826d1a6d.nnue` (Stockfish 13 default, HalfKP 256x2-32-32) | last official HalfKP net; reference = Stockfish `sf_13` |
| Phase-2 pin | Stockfish `sf_17.1`, `nn-1c0000000000.nnue` (big) + `nn-37f18f62d772.nnue` (small) | newest release whose inputs are plain HalfKAv2_hm; later nets add threat inputs, a much larger surface to reproduce bit-exactly |
| Nets in git | not committed; `make net` downloads and SHA-256-checks them, the build embeds them | 75 MB binaries do not belong in history; same as Stockfish |
| Make/unmake | `StateInfo` stack with undo; copy-make comparison recorded in the report | spec §4 |
| Magics | precomputed constants (generated by `tools/`), PEXT under `USE_PEXT` | no startup search, same tables on every machine |
| Dependencies | none in the engine | spec §15.5 |

## Deviations forced by this build environment

The work is done in a cloud container (4 vCPU Xeon, AVX-512), not on the two
target machines. Consequences, stated once here and repeated next to every
number in the report:

1. **No measurement on the real devices.** The `x86-64-sse41-popcnt` build is
   compiled and tested here (same instruction set as Ivy Bridge, different
   CPU). NEON code is compile-checked/emulated only if a cross toolchain can
   be installed; otherwise it is unverified until built on the Mac. NPS
   figures here are not the figures of either Mac.
2. **fastchess / cutechess-cli cannot be downloaded here.** SPRTs use
   `tools/sprt.py`, a small runner written for this repo: paired games from
   the UHO book, pentanomial statistics, normalized-Elo LLR, same bounds as
   the spec. It is a stand-in, not a replacement; the same tests should be
   repeated with fastchess on the Apple Silicon machine.
3. **Time controls are shorter than STC 10+0.1** to fit the hardware budget.
   The control used is written next to each result. No LTC runs here.
4. **Spec §10.4 route 2 (SPRT on Apple Silicon + non-regression on Intel)
   cannot be completed from here.** Results from this container are
   provisional evidence under that rule, and are labelled so.
5. **M9 (OpenBench / Fishtest)** needs a server and workers. The engine side
   (Makefile interface, `bench` output, `Bench:` lines) is delivered; the
   framework run is left to do.
